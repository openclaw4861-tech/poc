Construction Software Brief

November 11, 2026

Weekly Construction Software Briefing Pacific Glazing Corporation | Steve Watts, CEO November 11, 2026

1. Executive Summary

The open-source AEC stack is now operational for production glazing workflows, with browser-native IFC kernels and open construction-PM platforms eliminating per-seat licensing costs while matching legacy commercial capability. For PGC, this means direct quantity extraction from IfcCurtainWall and IfcWindow elements in a standard browser and a portable replacement for Procore and Autodesk Construction Cloud issue tracking. An 18-to-24-month strategic window remains before commercial AI platforms lock equivalent features behind restrictive SaaS APIs, making immediate evaluation critical. This week’s priority is to validate low-friction takeoff and issue-tracking pilots that reduce dependency on aging Autodesk runtime environments.

3. Open Source Spotlight

ThatOpen Components + web-ifc - Setup complexity: Medium. Requires an npm/Node.js build pipeline. Verify scoped package names (e.g., @thatopen/components) and pin dependency versions before production use; avoid deprecated keywords like ifc.js. - Maturity: Operational. Weekly download volume confirms enterprise reliance. The stack is production-viable today for browser-based takeoff, though the misleading v0.0.x semver on web-ifc demands manual version vetting. - PGC relevance: Immediate zero-license viewer and quantity extraction from curtain-wall IFC models.

OpenProject - Setup complexity: Low to medium. Docker containers are well-documented, and a cloud-hosted option exists for teams wanting zero local infrastructure. - Maturity: High. At 17,243 stars, it is the most mature open construction-PM platform available, with proven BCF/IFC topic tracking. - PGC relevance: Portable migration path from proprietary construction clouds while preserving issue-data ownership.

pascalorg/editor - Setup complexity: Medium to high. The browser client deploys easily, but enabling MCP/agent hooks for scan-to-BIM requires scan-data pipeline configuration and cleanup workflows. - Maturity: Rising fast. Strong community traction at 25,441 stars, yet agent-driven facade extraction should be treated as pilot-grade, not release-grade, until behavior is deterministic on your project types. - PGC relevance: Reduces desktop CAD reliance for as-built floor-plan generation and curtain-wall condition capture.

4. Try It This Week

A. Browser-Based Glass Takeoff with web-ifc + ThatOpen Components - Action: Load one live bid’s IFC model into a local browser viewer using @thatopen/components and web-ifc. Isolate IfcCurtainWall and IfcWindow instances to cross-check glass quantities against your current takeoff. - Who: Estimating team. No Autodesk viewer license required.

B. OpenProject BCF Issue Tracking - Action: Spin up an OpenProject instance (Docker or cloud trial) and import the BCF topics from a current facade project. Test the native IFC-linked issue workflow against your existing Procore or ACC process. - Who: Project managers and field engineers. Data remains fully portable.

C. As-Built Verification with CloudCompare - Action: Download CloudCompare and load a recent site laser scan. Overlay the point cloud against the fabrication model to verify mullion alignment and flag deviations before glass release. - Who: VDC and shop-drawing team. Free desktop install; no subscription required.

5. Ones to Watch

SolidCraft - Early-stage generative fabrication tool flagged for custom extrusions and bracketry evaluation within 6–12 months. For PGC: potential automation of unique glazing hardware generation. Not yet cleared for structural-release workflows; monitor repository releases and portfolio updates.

text-to-cad - Emerging generative CAD category for detail generation. For PGC: could reduce manual CAD labor on custom facade connectors and anchors. Track alongside SolidCraft for pilot eligibility in mid-2027.

Agent-Driven Scan-to-BIM Ecosystem (MCP hooks) - The Model Context Protocol integrations inside rising editors (e.g., pascalorg/editor) are stabilizing but unstandardized. For PGC: promises automated facade extraction from scans, yet interoperability remains unproven. Restrict to non-critical pilot projects until agent output is deterministic and repeatable.
