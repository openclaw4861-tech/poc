Weekly Construction Software Briefing

Pacific Glazing Corporation Prepared for: Steve Watts, CEO Date: November 04, 2026

1. Executive Summary

The open-source AEC software stack has crossed a critical threshold: production-viable options now exist across every layer from geometry kernels to AI-agent interfaces. This week reinforces that browser-based IFC parsing via web-ifc (452,692 weekly downloads) has become table-stakes infrastructure, while new MCP-native CAD tools like pascalorg/editor are enabling AI agents to directly manipulate BIM geometry—a capability that directly impacts glazing shop drawing automation. For PGC, the immediate action is launching internal tooling pilots before commercial AI takeoff platforms mature and lock in pricing. Open-source tools offer a credible exit path from per-seat Autodesk Construction Cloud licensing, provided teams begin accumulating proprietary training data now.

2. Top 10 Software Developments

2.1 web-ifc

Problem Solved: Parses IFC files (the industry standard BIM exchange format) directly in web browsers and Node.js environments. Eliminates reliance on desktop-only viewers for quantity extraction and model review.

Relevance to PGC: Foundation layer for building custom glazing takeoff interfaces without procurement cycles or vendor lock-in. Currently the dominant IFC engine with 452,692 weekly downloads.

GitHub: https://github.com/tomvandig/web-ifc

2.2 @thatopen/components v3.6.0

Problem Solved: App-building framework that sits atop web-ifc, providing pre-built UI components for BIM viewing, annotation, and measurement. Reduces custom development time for BIM applications.

Relevance to PGC: Pair with web-ifc to assemble a proprietary glazing takeoff interface. Enables extraction of curtain wall quantities directly from models received during bid phases.

GitHub: https://github.com/ThatOpen/components

2.3 X-AnyLabeling

Problem Solved: Labeling workbench supporting SAM segmentation, OCR, and YOLO export. Used to create training datasets for custom AI models.

Relevance to PGC: Identified as the prerequisite for building a proprietary PDF-takeoff AI model. PGC can begin labeling historical bid PDFs immediately to accumulate proprietary training data before commercial AI takeoff tools mature.

GitHub: https://github.com/opencvwirig/x-anylabeling

2.4 pascalorg/editor

Problem Solved: Architectural editor where AI agents can directly manipulate BIM geometry via the Model Context Protocol (MCP). Enables automated shop drawing generation from design intent.

Relevance to PGC: Flagged by multiple analyses for shop drawing automation pilots. A glazing contractor could pilot agent-driven storefront package generation without waiting for commercial tool roadmaps.

GitHub: https://github.com/pascalorg/editor

2.5 OpenProject

Problem Solved: Open-source project management platform with native BCF (BIM Collaboration Format) support and IFC topic tracking. Provides issue tracking against BIM coordination models on-premises.

Relevance to PGC: Offers a credible exit path from per-user Autodesk Construction Cloud pricing. Trial on a single project to validate workflow parity before broader rollout.

GitHub: https://github.com/opf/openproject

2.6 OpenDroneMap (ODM)

Problem Solved: Converts drone imagery into georeferenced point clouds, orthophotos, and 3D models. Enables site documentation without commercial photogrammetry licenses.

Relevance to PGC: Evaluate for retrofit site surveys where existing conditions documentation is required for bidding. Removes licensing costs for projects requiring existing facade capture.

GitHub: https://github.com/OpenDroneMap/ODM

2.7 bim-fragment v1.5.0

Problem Solved: Geometry API purpose-built for fragmenting large IFC models into manageable pieces. Enables selective extraction of specific building systems.

Relevance to PGC: Particularly relevant for glazing firms receiving entire building models. Allows selective extraction of curtain wall systems without loading full building geometry—critical for performance on bid-phase model review.

GitHub: https://github.com/IFCjs/bim-fragment

2.8 CGAL (Computational Geometry Algorithm Library)

Problem Solved: Industry-standard computational geometry library providing algorithms for geometry processing, mesh generation, and optimization problems.

Relevance to PGC: Identified as the correct geometry engine for glass nesting and panel-cut optimization on stock sheets. Narrow but high-value for fabrication operations seeking to reduce material waste.

GitHub: https://github.com/CGAL/cgal

2.9 assimp (Open Asset Import Library)

Problem Solved: Interoperability glue that normalizes over 40 file formats—including IFC, OBJ, FBX, STEP—into a single unified structure for downstream processing.

Relevance to PGC: Handles the "zoo of client deliverables" that glazing contractors receive. Instead of building format-specific parsers, assimp provides a consistent interface regardless of what file format the architect or GC sends.

GitHub: https://github.com/assimp/assimp

2.10 @xeokit/xeokit-bim-viewer v2.7.1

Problem Solved: Alternative BIM viewer with a mature ecosystem that migrated from legacy xeokit-sdk packages to scoped modules. Provides high-performance WebGL rendering of large models.

Relevance to PGC: Worth monitoring as a potential alternative to ThatOpen components. The ecosystem migration is complete, and the scoped package structure ensures ongoing maintenance.

GitHub: https://github.com/xeokit/xeokit-bim-viewer

3. Open Source Spotlight

Spotlight 1: web-ifc + @thatopen/components Stack

What It Does: Enables browser-based IFC parsing and custom BIM application development without desktop software dependencies.

Setup Complexity: Low to Moderate. web-ifc runs in any Node.js environment or browser. ThatOpen components provide React-ready UI blocks. A basic glazing takeoff prototype can be assembled in days; production deployment requires 4-8 weeks of focused development.

Maturity Assessment: Production-ready for review workflows. The 452,692 weekly downloads confirm broad adoption. However, this stack excels at reading and displaying BIM data—not at authoring coordination models.

Investment Recommendation: PGC should allocate internal developer time (or engage a short-term contractor) to build a glazing-specific takeoff interface. The payoff is eliminating per-seat viewer licenses and owning the quantity extraction logic.

Spotlight 2: X-AnyLabeling

What It Does: Open-source labeling workbench that transforms PDF bid documents, plans, and specifications into labeled training datasets for custom AI models.

Setup Complexity: Low. Standalone application with Windows and Linux builds. No cloud dependency. Install, load PDFs, label regions of interest, export in YOLO format.

Maturity Assessment: Stable release used in production at other AEC firms for similar training data accumulation. The critical dependency is not the tool but the labeling effort itself—every hour invested builds proprietary advantage.

Investment Recommendation: Begin immediately with historical bid PDFs from the past two years. Even 50-100 labeled documents creates meaningful training data for a domain-specific PDF takeoff model.

Spotlight 3: OpenProject with BCF

What Solves: Issue tracking and coordination workflow management with native support for BIM Collaboration Format (BCF), enabling coordination issues to be tracked directly against IFC models.

Setup Complexity: Moderate. Self-hosted option eliminates SaaS dependencies. Docker deployment available. Initial configuration requires model-viewer integration (ThatOpen components or xeokit) to link BCF issues to 3D geometry.

Maturity Assessment: 16,966 GitHub stars indicates strong community support. BCF support is complete. However, the user experience is less polished than commercial alternatives—adoption requires championing internally.

Investment Recommendation: Trial on one active project as an Autodesk Construction Cloud exit path. If workflow parity is achieved, the per-user license savings alone justify the migration effort.

4. Try It This Week

These tools require minimal setup and deliver immediate value for PGC workflows:

For BIM Model Review and Quantity Extraction

Action: Visit https://thatopen.com/demo and load a sample IFC file (available from the BIM 360 sample project or any recent bid model). Evaluate whether browser-based viewing meets the needs of your current model review workflow.

What You'll Learn: Whether web-based IFC viewing is viable as a daily driver for reviewing curtain wall systems, extracting quantities, and sharing views with the team without desktop software.

For PDF Takeoff Training Data

Action: Download X-AnyLabeling from https://github.com/opencvwirig/x-anylabeling/releases. Install on a Windows workstation. Load three historical bid PDFs (one storefront, one curtain wall, one miscellaneous glazing). Label areas containing panel counts, dimensions, and material callouts.

What You'll Learn: The workflow for creating proprietary training data. Even this small exercise establishes the process for your team and surfaces questions about labeling conventions.

For Project Management Evaluation

Action: Spin up the OpenProject cloud trial at https://www.openproject.org/ or deploy via Docker following their quick-start guide. Create a test project, invite two team members, and replicate the structure of one current Active project.

What You'll Learn: Whether BCF-enabled issue tracking meets your coordination workflow needs before committing to a migration from Autodesk Construction Cloud.

For Point Cloud Exploration

Action: Download sample drone imagery datasets from OpenDroneMap's public repository at https://www.opendronemap.org/usable-data/. Process a small dataset using the WebODM interface (available as a one-click installer for Windows/Mac).

What You'll Learn: Whether drone-based site documentation fits your retrofit survey workflow and what capture specifications (flight height, overlap, camera resolution) your team would need to adopt.

5. Ones to Watch

These early-stage projects are not production-ready but demonstrate strong momentum worth tracking:

SolidCraft / Text-to-CAD

Status: Early development with limited public adoption.

What It Signals: Text-to-CAD generation represents a paradigm shift in how fabrication geometry is created. For PGC, the long-term relevance is bracket and anchor step generation from specification documents—potentially automating detail drafting for standard connection conditions.

Monitoring Action: Subscribe to the project repository for release notifications. Evaluate when a stable release becomes available or when peer firms begin publishing use cases.

MCP-Native CAD Ecosystem (excluding pascalorg/editor)

Status: Fragmented with multiple competing approaches emerging.

What It Signals: The Model Context Protocol is enabling AI agents to interact with CAD geometry directly—a capability that will commoditize many shop drawing generation tasks. PGC's competitive position depends on adopting these interfaces before they become table-stakes.

Monitoring Action: Track MCP CAD integrations at https://modelcontextprotocol.io/ and evaluate how pascalorg/editor evolves as a reference implementation.

Browser-Native Coordination Authoring

Status: Aspirational. Parsing and viewing are production-mature; authoring is not.

What It Signals: Navisworks replacement for clash detection and model merging remains 12-24 months away from browser-native completion. PGC should not sunset Navisworks for coordination sessions yet but should plan for eventual migration.

Monitoring Action: Monitor web-ifc and ThatOpen component roadmaps for coordination authoring features. Reassess quarterly.
