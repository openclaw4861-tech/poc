1. Executive Summary

This week's analysis confirms that the open-source AEC ecosystem has reached a critical inflection point: browser-native BIM viewing is now production-viable without commercial licensing, eliminating a significant cost center for PGC. The most actionable development is the combination of ThatOpen Engine and web-ifc, which together provide enterprise-grade model review capability directly in the browser. For glazing-specific workflows, the emerging AI-agent BIM editing through pascalorg/editor represents a paradigm shift in how shop drawings could be generated, though pilot validation remains essential. The PDF takeoff gap persists as expected, but the strategic path forward—curating labeled training data internally—has never been clearer.

3. Open Source Spotlight

ThatOpen Engine + web-ifc — Production Infrastructure

Setup Complexity: Low (JavaScript libraries; CDN-hosted options available) Maturity: High (151,000+ weekly npm downloads; battle-tested in production environments)

This combination has crossed the threshold from promising to plumbing. The stack handles IFC parsing natively in the browser, enabling PGC to build internal model review portals without Autodesk licensing. Curtain wall type definitions, panel dimensions, and U-value specifications can be extracted programmatically—directly feeding estimating workflows.

Evaluation Path: Deploy a single glazing project model to a test environment this week using the web-ifc viewer template. Validate that Mullion/Transom geometry and glazing panel IDs render correctly before expanding to production.

pascalorg/editor — AI-Agent BIM Interaction

Setup Complexity: Medium (Node.js environment; MCP protocol configuration required) Maturity: Medium (25,000 GitHub stars; active development; production use cases emerging)

This tool represents the leading edge of AI-agent BIM workflows. Unlike traditional Revit API automation requiring C# expertise, pascalorg/editor exposes BIM data through the Model Context Protocol (MCP), allowing natural language commands to read and write IFC data. For PGC, this means a project manager could request "extract all curtain wall panel dimensions from the south facade" and receive structured output without touching CAD software.

Evaluation Path: Set up a contained pilot with one completed project. Train the AI agent on PGC's standard shop drawing outputs. Measure accuracy against manual extraction before expanding scope.

OpenProject — Coordination Workflow Replacement

Setup Complexity: Low (self-hosted or cloud; Docker deployment available) Maturity: High (established project; active enterprise deployments)

The integration of BCF (BIM Collaboration Format) management into OpenProject is the quiet headline for coordination teams. Clash issues can now be linked directly to IFC model viewpoints, replacing Jira/ACC Issues for coordination tracking at zero licensing cost. For PGC's field teams, this means anchor clashes and penetration conflicts are logged with exact model context—no more screenshot attachments and ambiguous descriptions.

Evaluation Path: Import one active project's clash report as BCF files. Validate viewpoint associations and assignability to glazing subcontractors.

5. Ones to Watch

These projects are early-stage but demonstrating strong technical momentum. Do not deploy in production; monitor for maturation.

solidcraft

GitHub: https://github.com/solidcraft/solidcraft Current Stars: ~8,400 Technology: Rust/WASM parametric CAD with MCP automation hooks

Why It Matters: If solidcraft reaches maturity, it could displace FreeCAD as the parametric CAD kernel for glazing detail work. Rust's memory safety and WebAssembly performance are architecturally superior to FreeCAD's C++ foundation. However, the ecosystem is thin today—limited importers, no mature rendering pipeline.

PGC Action: Bookmark the repository. Re-evaluate at Q2 2027 when the 1.0 release milestone is targeted.

Point Cloud Library (PCL)

GitHub: https://github.com/PointCloudLibrary/pcl Current Status: Mature C++ library; widely used in robotics and surveying

Why It Matters: As-built verification against BIM is a growing need for curtain wall retrofit projects. PCL provides the algorithmic foundation for point cloud registration, segmentation, and deviation analysis. CloudCompare (listed above) actually depends on PCL internally.

PGC Action: Monitor PCL's Python bindings maturity. If accessibility improves, evaluate for integration into PGC's field verification workflow for curtain wall replacement projects.

earthtojake/text-to-cad

GitHub: https://github.com/earthtojake/text-to-cad Current Stars: ~22,000 Current Output: STEP and STL formats; mechanically-oriented geometry

Why It Matters: Spider fittings, anchor plates, and custom brackets are mechanically-typed parts—exactly where this tool excels. As the model improves, natural language description of glazing connection details could reduce CAD drafting time for custom components.

PGC Action: Test current capabilities with a simple anchor plate description. Verify output geometry is compatible with standard fabrication workflows before expanding expectations.

Strategic Reminder: The PDF Takeoff Data Moat

No mature open-source PDF extraction tool exists today. This gap persists because the problem is fundamentally about training data, not algorithms. The durable competitive advantage for PGC is a labeled archive of glazing shop drawings—data that uniquely exists within the company.

Recommended action this quarter: Begin curating labeled training data using X-AnyLabeling. Even 50-100 labeled drawings create the foundation for a proprietary takeoff engine that outperforms any generic solution. Estimated timeline to internal capability: 12-18 months.
