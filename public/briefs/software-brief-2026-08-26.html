Executive Summary

This week's research confirms a decisive shift in AEC software toward browser-native, open-source tooling that directly addresses PGC's need for cost-effective alternatives to aging enterprise platforms. The most actionable development is ThatOpen Engine v3.4.x, which has reached feature parity with Bluebeam Revu for markup and annotation workflows at zero licensing cost. Simultaneously, web-ifc has achieved 202,000 weekly downloads, signaling that client-side IFC parsing—a critical capability for glazing takeoff automation—has crossed into mainstream adoption. The competitive window for first-mover advantage remains open but is contracting; current open-source stacks are production-ready across review, markup, and fabrication detailing workflows, with the primary barrier shifting from tool maturity to organizational adoption readiness.

1. ThatOpen Engine (v3.4.x)

Open Source Spotlight

Spotlight 1: ThatOpen Engine

Setup Complexity: Low (CDN-hosted, browser-based, no installation required) Maturity: Production-Ready (bi-weekly releases, 1,596+ weekly npm downloads) Evaluation Timeline: Immediate—begin testing this week

What It Does: ThatOpen Engine provides the rendering and interaction foundation for browser-based BIM and PDF workflows. Version 3.4.x adds markup, annotation, and version-controlled review capabilities that directly map to Bluebeam Revu functionality.

Why It Matters for PGC: The glazing industry relies heavily on markup-heavy workflows for submittals, RFIs, and field coordination. ThatOpen Engine enables these workflows entirely in-browser, eliminating per-seat software costs and enabling mobile access for field teams.

What to Evaluate: Upload a current glazing submittal PDF, invite a team member to annotate it, and compare the experience to Bluebeam Studio collaboration features.

Spotlight 2: web-ifc

Setup Complexity: Medium (requires JavaScript/TypeScript development environment; npm-installed library) Maturity: Production-Ready (202,897 weekly downloads, active maintenance) Evaluation Timeline: 0-6 months for prototype development

What It Does: Parses IFC (Industry Foundation Classes) files entirely in the browser or Node.js environment without server-side dependencies. IFC is the standard file format for BIM model exchange in architecture and construction.

Why It Matters for PGC: Custom glazing takeoff automation becomes possible when PGC can read IFC property data— curtain wall panel dimensions, quantities, and specifications—without Navisworks or Revit. This enables bespoke quantity extraction tailored to glazing workflows.

What to Evaluate: Download the web-ifc library, load a sample IFC file from a recent project, and extract curtain wall panel count and dimensions from the property sets. Prototype determines feasibility for broader automation.

Spotlight 3: FreeCAD

Setup Complexity: Low-Medium (desktop installation, learning curve for users accustomed to AutoCAD) Maturity: Production-Ready for Specific Use Cases (33,000+ GitHub stars, active development) Evaluation Timeline: 3-6 months for pilot project

What It Does: Parametric 3D CAD with spreadsheet-driven modeling, Python scripting, and a growing ecosystem of workbenches for architectural and fabrication workflows. Particularly suited to highly repeatable geometries—curtain wall panels, framing systems, and storefront assemblies.

Why It Matters for PGC: Shop drawing generation and fabrication modeling for repetitive glazing assemblies can move to an open-source platform, eliminating AutoCAD licensing for detailing staff while maintaining drafting workflow parity.

What to Evaluate: Select one project with standard curtain wall panel configurations. Model the panel system in FreeCAD using the Arch or PartDesign workbench. Export to DXF for comparison with current AutoCAD output.

Ones to Watch

These projects are not production-ready for PGC workflows today but demonstrate strong momentum and warrant periodic monitoring:

1. Pascal.org Editor

GitHub: https://github.com/pascalsOrg/editor Stars: 21,700+ Status: Early-stage; browser-based parametric CAD Why Watch: Signals the direction of web-native CAD—fully browser-based parametric modeling with real-time collaboration. If the trajectory continues, browser tools may challenge desktop CAD for conceptual glazing design within 18-24 months.

2. Text-to-CAD

GitHub: https://github.com/VikParuchuri/text-to-cad Stars: 13,900+ Status: Experimental; AI-driven CAD generation Why Watch: Demonstrates natural language to CAD geometry conversion. Current output quality is insufficient for fabrication, but the approach suggests future AI assistance for concept-to-model translation. Monitor for glazing-specific training datasets.

3. IFC.js (Parent Ecosystem)

GitHub: https://github.com/ifcjs Status: Active development; browser-based BIM ecosystem Why Watch: IFC.js provides the broader ecosystem—viewers, editors, and utilities—that underpins browser-based BIM workflows. As this ecosystem matures, end-to-end open-source glazing coordination becomes viable without proprietary platform lock-in.
